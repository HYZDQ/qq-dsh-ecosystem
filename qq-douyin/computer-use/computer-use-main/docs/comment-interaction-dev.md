# 抖音评论互动开发文档（评论区自动回复 · 多轮对话 · @豆包求助）

- 状态：需求评审稿（未实现）
- 日期：2026-10-29
- 范围：dsh-douyin-agent（抖音工具面）+ computer-use 引擎层（comment-browser / autonomous-comments）
- 前置调研：GitHub 开源实现 + 网上实践资料（见文末「参考资料」）

---

## 1. 背景与目标

现在大肥鱼在评论区只有「手动工具」：`douyin_comments`（读评论）、`douyin_comment_reply`（发/回评论）、`douyin_at_me`（读「@我」通知）、`douyin_notices`（读通知）、`douyin_comment_mention`（评论区@人）。没有**常驻的评论互动循环**——别人 @ 机器人或问它问题，它感知不到，更不会自己回。

本特性要补上这条闭环，覆盖四条需求：

| # | 需求 | 一句话 |
|---|------|--------|
| R1 | 随时回复 @ | 我在任意作品评论区 @ 机器人，它能感知并回复我的评论 |
| R2 | 多轮对话 | 机器人 @ 我后，我回复它，它能继续回我（不是一锤子买卖） |
| R3 | 回复路人 | 别人在评论区询问机器人，它也能回复别人 |
| R4 | @豆包求助 | 遇到答不上的问题，机器人在评论区 @ 豆包提问，拿到答案后再回 |

## 2. 需求明细

### R1 我 @ 机器人 → 它随时回复

- **触发**：任意作品评论区出现 @ 机器人的新评论（通知 type 45/46，或作品评论扫描兜底）。
- **行为**：
  1. 值班轮询发现新 @（水位线去重，只处理新增）；
  2. 读取被 @ 的评论上下文（作品、评论内容、楼中楼父链）；
  3. 用人格生成回复，`douyin_comment_reply` 回到**正确的楼中楼位置**；生成前**采样 2 帧视频画面** + 作品标题/作者进上下文（2026-10-29 升级为画面采样版；模型不接收画面时退回文字并留痕）；
  4. 每次回复推 QQ 通知主人（复用现有 `sendToOwner` 摘要通道）。
- **"随时"的量化**：轮询间隔目标 60~120 秒（对照通知接口的未读计数做增量拉取），不承诺实时。
- **验收**：
  - 手机端在任意作品 @ 机器人提问，≤3 分钟内看到回复（正常网络）；
  - 同一条评论只回一次（去重可靠，重复轮询不重发）；
  - 回复挂在目标评论的楼中楼下（不是发成新评论）。

### R2 机器人 @ 我后，我回复它 → 它继续回

- **触发**：机器人发出的评论（含 @ 对方的评论）收到了新的回复/追评，且来自主人或被 @ 的对象。
- **行为**：
  1. 线程模型记住「这条根评论是机器人发起的对话」（root_cid → 参与者、轮次）；
  2. 对方回复后继续回，形成多轮；**每条线程默认最多 3~5 轮**（可配置），防止刷屏和循环自嗨；
  3. 轮次到顶或对方不再回 → 线程归档，不再主动续话。
- **验收**：
  - 我回复机器人后 ≤3 分钟内它回我；连续对 3~5 轮都成立；
  - 别人插话到这条线程时按 R3 规则处理，不把两人的对话搅在一起；
  - 线程轮次到顶后明确不再回（不算失败）。

### R3 别人询问机器人 → 回复别人

- **触发判定**（满足其一）：
  - 评论 @ 了机器人（与 R1 同源，但来自主人之外的人）；
  - 评论文本命中「询问机器人」模式（含"机器人/大肥鱼/问一下/怎么/为什么"等问句特征，用模型判别兜底）。
- **行为**：同 R1 的回复流程，但**回复对象是路人**。
- **边界（使用者已拍板的默认策略，均可在「刷抖音」设置页改）**：
  - 默认只回「@机器人」和「明确提问」两类；普通聊天、表情、引战、广告一律不回；
  - **不限次数**（使用者决策：不设每人/全局限额）；护栏保留：随机发送间隔、文案清洗、每线程轮次上限；
  - 敏感词/广告/引战命中 → 只通知主人，不自动回。
- **验收**：
  - 路人 @ 提问能收到回复；闲聊刷屏不回复；
  - 超限额后安静跳过并记账，不报错、不重试；
  - 主人可在设置页关闭「回复路人」，只保留 R1/R2。

### R4 遇到不懂的问题 → 评论区 @ 豆包求助

- **触发**：R1/R3 的问题机器人判定「答不了/不确定」（模型自评 confidence 低或问题涉实时信息），且求助开关开启。
- **行为**：
  1. **发一条独立的新评论** @ 豆包官方账号并附上问题（不是回复豆包的旧评论——豆包无上下文记忆，回复它不会再触发）；
  2. 轮询自己这条评论的回复（豆包回复延迟约 1 分钟内，测试期不稳），拿到豆包回答；
  3. 把豆包答案作为参考，按人格改写后回到提问者（注明"我问了豆包"或直接引用，按人格决定）；
  4. 超时（默认 5 分钟）没等到豆包回复 → 兜底：诚实告知"这个问题我暂时答不好"，并向主人推送求助记录。
- **豆包机制的硬约束（调研结论，设计必须遵守）**：
  - 必须准确 @ **豆包官方账号**，山寨号不触发；
  - 每条 @豆包 评论是**独立会话**，豆包不记上下文，回复它也不会再触发；
  - **单条视频、同一账号通常只回复一次**：同一视频的后续问题大概率不回 → 同一视频的多个问题要**聚合成一次提问**；问完一次后，该视频再有新问题→要么直接答、要么换视频问；
  - 触发方式唯一：主动 @豆包 并提问；他人追评不触发；
  - 延迟不定（约 1 分钟内，偶发不回）。
- **验收**：
  - 发出 @豆包 提问后能等到回复并被正确引用（正常情况）；
  - 豆包不回时 5 分钟内兜底收尾，不留悬挂状态；
  - 同一视频第二次求助不再重复 @豆包（或聚合后一次问完），不制造无效评论。

### 3.2 豆包评论区机制（R4 的事实依据）

来源：[补发一条关于豆包在抖音中回复评论的帖子（天坦茶馆）](https://bbs.tatans.cn/topic/111425)（含与豆包官方对话实录）：

- 2025-03 起测试、2025-11 放量、2026-01 相对稳定；豆包多模态读取视频内容作答；
- @豆包**官方账号**才触发（山寨号无效）；
- **无上下文记忆**：每条 @豆包 评论是独立会话，回复它的评论不会再触发；
- **单视频单账号通常只回一次**，重复/相近问题大概率不回；
- 回复延迟约 1 分内，偶发不回（网络/账号状态/提问方式影响）；
- 想连续问 → 私信豆包（可带视频链接连续对话）——本特性不做私信豆包，留作扩展。

### 3.3 工程实践要点（CSDN 部署实践提炼）

- **去重**：`cid` 为主键的 comments 表 + replies 表（target_cid 唯一），"是否已回"用 `answered_by_me` + replies 双重判定；候选筛选 = 未回 ∧ 非风险 ∧ 非自己 ∧ 未发过回复，按时间升序；
- **楼中楼参数坑**：`reply_id` = **根评论 cid**，`reply_to_reply_id` = **目标子评论 cid**；两个都填子评论会"返回成功但挂错位置"；
- **风控**：回复"短、具体、不引流"；发送前清洗（去 URL、**去 @** 防误触发提醒、压缩空白、超 60 字截断）；发送间隔随机 3~8 秒；限额按用户计（同用户 24h 上限）；敏感词只通知不回；
- **发送通道**：一律页面上下文 `fetch` 复用签名/Cookie（与我们 `douyin_comment_reply` 一致）。

> ⚠️ **现状缺陷（顺带修）**：`douyin_comment_reply` 目前把 `reply_id` 和 `reply_to_reply_id` 都填同一条 cid——回复**子评论**会挂错位置。实现本特性时改为：工具参数显式区分 `root_cid` 与 `reply_cid`，无 root 时按现有单 ID 处理。

## 5. 方案设计

### 5.1 总体结构

```
                    ┌────────────────────────────────────────┐
                    │  comment-duty 值班循环（60~120s 一拍）  │
                    │  类比 chat/spark 的 dutyState 自拉起     │
                    └───────┬────────────────────────────────┘
        ┌───────────────────┼─────────────────────┐
        ▼                   ▼                     ▼
  触发源 A：通知增量     触发源 B：作品评论扫描    触发源 C：线程内新回复
  douyin_at_me/         douyin_comments（有新      replies 水位（R2 续话）
  notices 未读计数       @/问句时才拉详情）
        └───────────────────┼─────────────────────┘
                            ▼
                  候选筛选（去重/限额/敏感词/范围）
                            ▼
                  意图分类（R1 我@ / R2 续话 / R3 路人问）
                            ▼
                ┌───────────┴───────────┐
                ▼                       ▼
         人格生成回复              「答不了」→ R4 @豆包求助
                │                       │
                └───────────┬───────────┘
                            ▼
            douyin_comment_reply（楼中楼正确挂载 + 回读核实）
                            ▼
              记账（replies 表 + 线程轮次）＋ QQ 推送主人
```

### 5.2 数据模型（新状态文件 `comment-duty.json` + `comment-threads.json`）

```jsonc
// comment-threads.json：一次对话 = 一条线程
{
  "threads": {
    "<root_cid>": {
      "aweme_id": "...", "kind": "owner|friend|stranger|expert",
      "participants": [{ "uid": "...", "nick": "...", "role": "owner|target|stranger" }],
      "turns": 3, "maxTurns": 5,
      "status": "active|archived|gave_up",
      "pendingExpert": { "askCid": "...", "question": "...", "askedAt": 1793..., "deadline": 1793... },
      "lastSeenCid": "...", "updatedAt": "..."
    }
  },
  "watermark": { "noticeSeq": 0, "byAweme": { "<aweme_id>": { "lastCreate": 0, "seenCids": [] } } },
  "limits": { "byUser24h": { "<uid>": { "count": 0, "resetAt": 0 } }, "byDay": { "2026-10-29": 0 } }
}
```

- **水位线**：@我通知按未读计数增量拉取；作品评论按 `create_time` + cid 去重（cid 主键天然幂等）；
- **线程轮次**：R2 多轮上限默认 5，到顶归档；
- **限额**：按人 24h 滑动窗 + 按天全局，语义与现有额度一致（0=无上限）。

### 5.3 意图分类与回复范围

| 输入 | 分类 | 默认是否回 | 备注 |
|------|------|-----------|------|
| @机器人（来自主人） | R1 | ✅ 回 | 无限额（主人优先） |
| 机器人线程内新回复（主人/被@者） | R2 | ✅ 回 | 受 maxTurns 限制 |
| @机器人（来自路人） | R3 | ✅ 回 | 受每人/全局限额 |
| 路人问句（无@） | R3 | ⚠️ 默认关 | 「回复路人」开关打开才回 |
| 广告/引战/敏感词 | — | ❌ 不回 | 只推送主人 |
| 表情/闲聊/无意义 | — | ❌ 不回 | 静默跳过 |

分类实现：先规则（@检测、问句模式、敏感词表），存疑的用决策模型一次判别（计入模型请求预算）。**不确定时宁可不回**（fail-closed，与全域风格一致）。

### 5.4 R4 @豆包求助流程

1. 触发：问题被判「答不了」且 `expertAsk.enabled`；
2. **聚合提问**：同一线程/同一视频的待问问题合并为一条评论，格式大致为：
   `@豆包 <问题摘要（≤80字）>（帮我解答一下）`——发**新评论**，不回复豆包旧评论；
3. 等待：轮询该评论的子回复（豆包昵称/官方 uid 校验），超时默认 5 分钟；
4. 命中：把豆包回答带回线程，按人格改写后回复提问者；
5. 兜底：超时/没回 → 诚实告知 + QQ 推主人；
6. **配额**：每视频最多 1 次 @豆包（豆包机制限制），每天最多 N 次（默认 10，可配置）；
7. 失败重试：@豆包评论**发送失败**可重试（瞬态），但"发出后没回"不重发（避免重复无效评论）。

### 5.5 风控与安全（硬性约束）

- **不限次数**（使用者决策）；发送间隔随机 3~8 秒（叠加在现有写操作熔断之上）；
- 文案清洗：去 URL、去多余 @、压缩空白、≤60 字（豆包提问 ≤80 字）；
- 每线程轮次上限（默认 5，设置可改）；
- 敏感词/广告/引战 → 不回 + 通知主人；
- 连续发送失败沿用 `outbound-guard` 熔断（现有）；
- 评论内容不含人格隐私、不引用 QQ 私聊内容（现有公开评论红线，沿用）。

### 5.6 设置页（「公开评论」栏目下新增「评论互动」）

- 开关：回复我的 @（默认开）/ 多轮对话（默认开）/ 回复路人（默认关）/ @豆包求助（默认关）；
- 限额：每人 24h、全局每日、线程轮次、豆包每日次数、轮询间隔；
- 豆包：官方账号昵称/uid 校验值、超时分钟数；
- 状态：当前活动线程数、今日已回、豆包求助记录；
- 「说停即停」：值班开关 + `douyin_comment_duty_stop` 工具。

### 5.7 工具面变更（QQ 机器人与引擎共用）

| 工具 | 动作 |
|------|------|
| `douyin_comment_duty_start/stop/status` | 新增：值班循环开关与状态 |
| `douyin_comment_reply` | 修改：`reply_id` 拆成 `root_cid` + `reply_cid`（修楼中楼挂载） |
| `douyin_ask_expert` | 重做：发 @豆包 提问 + 等回复 + 兜底（旧版已删，新版按 5.4） |
| `douyin_at_me` / `douyin_comments` | 不变（触发源复用） |

QQ 侧 `qq-tool-restrict` 放行策略：默认只放行 `douyin_comment_duty_status` 与 `douyin_at_me` 等只读；写操作（回复/求助）由值班循环在插件侧执行，QQ 机器人仍不直接外发评论（沿用现有"评论类工具不放行给 QQ"的红线，主人在 QQ 里点名要求时再单独放行）。

## 6. 边界、风险与未决问题

1. **通知接口不是实时**：type 45/46 有延迟/丢漏风险 → 用作品评论扫描兜底，但只能覆盖"我们发过内容的作品"，纯路人视频下的 @ 靠通知源；
2. **豆包可能不回**：5 分钟超时兜底；豆包规则（单视频一次）随平台迭代可能变化，做成可配置校验（昵称/uid、超时、每视频次数）；
3. **风控红线**：任何自动外发都有封号风险，限额默认保守，命中风控迹象（发送连续失败/验证码）立即停摆唤人（复用 `flagLoginLost` 通道）；
4. **已定决策（2026-10-29 使用者拍板）**：
   - 「回复路人」**默认关**，开关放进「刷抖音」设置页「评论互动」栏目，随时可改；
   - **不限次数**：不设每人/全局回复限额；
   - 豆包回答后，机器人把**总结推给主人**（QQ），并转答给提问者；豆包不回则如实兜底；
   - 多轮对话上限**默认 5 轮**，设置页可改（1~20）。
   - ⚠️ 唯一需要使用者配置一次的：**主人的抖音昵称**（设置页「评论互动」里填），用来区分"我"和路人——不填则所有 @ 都按路人处理（默认不回）。

## 7. 里程碑与验收

| 里程碑 | 内容 | 验收 |
|--------|------|------|
| M1 | comment-duty 值班循环 + R1（@我自动回复）+ 楼中楼参数修复 | 手机 @ 机器人 3 分钟内回复且挂载正确；重复轮询不重发 |
| M2 | R2 线程多轮 + R3 路人问答 + 限额/风控 | 连续 3~5 轮对话成立；路人闲聊不回；超限静默 |
| M3 | R4 @豆包求助（聚合提问/等待/兜底） | 等到豆包回复并引用；不回时 5 分钟兜底；同视频不重复问 |
| M4 | 设置页 + QQ 摘要推送 + 回归测试 | 设置可开关可调参；每轮互动有 QQ 摘要；全量测试绿 |

回归原则（沿用项目惯例）：入口可加载断言 + 新状态文件幂等 + 额度语义（0=无上限）测试 + 楼中楼挂载参数断言。
